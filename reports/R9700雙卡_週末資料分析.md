# 雙R9700 週末資料收集＋分析（11/21–22）

任務：唔等官方、唔加外置卡，專心發展雙 R9700。呢份係彈药儲備，星期一 EXPO 窗之後照住打。

## A1. SageAttention-RDNA4（最高性價比，Windows 直接落生產）
- **IxMxAMAR/SageAttention-RDNA4**：Windows drop-in build（SageAttention 2.2 ＋ gfx12 port PR#368 ＋ 手寫 HIP kernel，head_dim 128 fp16/bf16）。行 ComfyUI 標準 `--use-sage-attention` 旗，冇節冇改碼
- 佢啲手寫 kernel 對 PR#368 原版：causal fp16 **快 1.5–2.0x**、non-causal 1.06–1.3x
- 同卡 R9700 實測基準（sorenfalch 容器）：H3 fp8 i2v 640² 5s 有聲 20步 **3:19→2:39**；turbo-8 **1:17→1:02**；turbo-4 **0:38→0:31**。出圖（SDXL 1024²）無著數，唔好為出圖開
- ⚠ 要核對：社群 wheel 係 cp312，我哋生產 venv 係 **py3.13.17**——要搵佢有冇 cp313 版／source build（WSL build 反出 win wheel 都得）
- 成本：半日（含 A/B：warm seed A／timed seed B 鐵律，H3 640²＋1344×768 兩場）

## A2. WGPKernels INT8 GEMM（版本完全 match，未試水）
- 準 wheel：`https://github.com/deepbeepmeep/WGPKernels/releases/download/v1.4.2/wgpkernels-1.4.2+rocm100-py3-none-win_amd64.whl`
- 我哋生產 venv ＝ **torch 2.13.0+rocm10.0.0 / py3.13**（今日實測確認）——wheel 標註正係為 RDNA4＋torch 2.13.0/ROCm 10.0（experimental），py3-none 即 py3.13 啱食
- 來源：WanGP（deepbeepmeep）自研 INT8 kernel，宣稱精度高於其他 fast INT8 backend；backend auto 順序 WGPKernels→HIP→Triton→PyTorch，失敗自動跌落，風險低
- 下一步：clone 生產 venv 做 test venv（或 venv312），裝 wheel，Wan/H3 同 prompt 同 seed A/B；GEMM 係 H3 大頭，呢舊係最大未食水

## A3. Radiance TP2 雙卡合體（旗艦著，生態比預期成熟好多）
- **StillDeadcode/radiance 2.2.0**：C++/HIP 推理 server，HTTP 食 OpenAI API（/v1/videos、/v1/images、/v1/chat…）。官方 serving 設定就係「two 32 GB R9700」；gfx1201 kernel 預砌（libr4d）；Linux docker（我哋 WSL2＋DXG 兩卡都睇到）
- 模型目錄直接有數：**minimax-h3-i8.rad 63GiB（tp2.yaml 官方指定）**、fasth3-8-step-v2-i8 65GiB（8步版）、qwen-image-2.1-iq8r 16GiB（tp1/tp2 出圖）、ltx-2.5 37GiB（單卡有聲片）、flux-3-klein 9.4GiB
- H3 官方口徑：「On two R9700s a 5.17s clip at 1344x768 takes…」（時間未抽到全文，setup 時核對）
- 雙卡效能不是笑話：Qwen3.8-Flash-Next IQR-V4（＝我哋 Strata 同一個 125B 家族）tp2 雙 R9700 decode **11.2ms/step**（2.1.0 版 12.4ms）——即 ~89 t/s 同我哋 Strata 88-94 打平，2.2 仲有 SuffixDecoding/自適應 MTP 等投機全家桶
- **rkcth/radiance fork**（2.2-based）：文字＋圖＋片同一個 listener，fleet 自動管模型載入/泊位——正正係我哋想要嘅「生成工作常開 Server」形態；蕾蕾/Coco 食 OpenAI API 比傳 ComfyUI workflow 簡單
- 成本：63GiB 下載（E: 尚 682G，企入 hf-download-queue 夜更）＋ WSL docker compose 半日
- 風險：同 ComfyUI 生產搶 VRAM——要排程（ComfyUI 唔忙先起 radiance，或干脆生成工作分家）

## A4. torch 2.15 / AOTriton-FlyDSL（搭單車，唔係主攻）
- PyTorch 官方博客確認：AOTriton 已為 RDNA4（gfx1201）帶 FlyDSL attention kernel——即 torch 2.15+rocm10.2 嘅 sdpa 可能自動行 FlyDSL
- FlyDSL PR#1220（gfx120x FlashAttention：bf16/fp16/fp8/int8/iu4，喺 torch 2.15.0a0+rocm10.2.0a 驗證）、PR#1282（SageAttention2 gfx120：Q/K INT4＋V FP8 prefill）——未入 stable，屬於第二輪升級
- ⚠ ROCm 10.2 known issue：ComfyUI 行 AOTriton backend 喺部分 Radeon 倒退——升級測試時 A/B 閘住，生產繼續 CK attention
